## Comments

- 2026-09-28: The core resolves `LocalAppData`, `WinDir`, and `ProgramData` and walks each Target's folders from the table in `src/targets.rs`. A Target lists plain folders, uses a shallow filename filter, or expands Chromium profiles. The UI groups rows under Windows, Browsers, and Developer, and hides absent Targets and empty Categories. Fixture tests cover the thumbnail filter (immediate files only, with no Minimum age), Chromium profiles (`Default` and `Profile <n>` only, with cookie, history, session, login, web data, and preference sentinels intact in four profiles), redirected profiles and cache folders, a profile replaced during Clean, and a multi-folder Target that is absent, complete, partial, or failed. A test fails when the filter matches every name, when every directory counts as a profile, when redirected child directories are followed, or when the filtered folder is walked recursively. A Clean that deletes only a zero-byte file while another folder is blocked reports partial, not failed. `cargo test --lib` passes 51 tests; `cargo clippy --all-targets -- -D warnings` passes.
- A non-elevated debug build, before the exclusions below, Scanned Kevin's real folders; Clean was not run. The checklist showed four Categories, hid the absent Brave and Firefox (and Yarn, which was excluded afterward), gave new IDs their Defaults, and kept the saved `windows-temp: false`. Crash dumps showed a partial `access denied` result, because `ProgramData\Microsoft\Windows\WER` requires elevation. Kevin's Selection file was restored afterward.
- Owner checks ran on Kevin's machine against scratch caches and a scratch browser profile, not in a disposable Windows installation. `scripts/owner-checks/damage.py` deletes a seeded random half of the files by default, as rejected deletions can. `interrupt.py` stops after 10-90% of the files in the core's traversal order, as an interrupted Clean does. Each check then runs the owner again. Concurrent package activity was not tested. The Windows Targets have no owner-behavior check.
- Kevin chose to admit the Targets with a passing owner check plus the Windows Targets that Windows Disk Cleanup also cleans, and to exclude the browser and app Targets that have no owner-behavior check until they are validated. The code, table, and PRD no longer contain Edge, Brave, Firefox, Discord, VS Code, or NVIDIA, the `AppData` root, Firefox profile expansion, or the Apps Category.
